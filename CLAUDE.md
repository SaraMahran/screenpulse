# Screenpulse agent guide

Screenpulse is a portfolio project for film and TV audience insights. This foundation uses TanStack Start, React 19, strict TypeScript, Vite, Tailwind CSS, shadcn/ui and Motion. Authentication, Postgres and a CMS are future work and are not configured.

## Structure

- `src/routes/`: file based routes. `__root.tsx` owns the document and shared layout. Add new routes here.
- `src/router.tsx`: router factory. `src/routeTree.gen.ts` is generated; do not edit it manually.
- `src/components/`: shared application components. `src/components/ui/` contains shadcn components.
- `src/lib/`: shared utilities.
- `src/styles.css`: theme tokens and global styles.
- `src/test/`: shared test setup. Put component tests beside components.
- Future server functions belong in `src/server/` using TanStack Start `createServerFn`. Do not add server functions until needed.

## Conventions and validation

Use TypeScript strict mode and never write `any` in authored code. Generated framework files are maintained by their generator. Use shadcn components and CSS theme tokens instead of raw colors. Keep server rendering as the default. Match the operating system color scheme through CSS. Motion is installed for future work; do not add animations without a task requiring them.

Run `npm run check` before saying a task is done and fix all failures. It runs type checking, ESLint, Prettier and Vitest in order. Run `npm run build` when changes affect application or build behavior.

## Repository and secrets rules

Never commit or push. Never create or stage plan or notes files in the repository. Keep plans and decisions in chat. Never create `.sql` migration files anywhere; provide any future database changes as SQL in chat. Never set a shared database connection pool to read only or run session level SET statements against one.

Never print, save or copy any password, token or key into reports, files or the repository. Never read `.env` files, process environment variables or process arguments. If a secret appears in output, state that one was shown without repeating it, then stop and tell the user. Never try to reach or look up any real user's password or credentials. Values generated by tests, including temporary passwords, mock connection strings and fixtures, are test data rather than secrets.
